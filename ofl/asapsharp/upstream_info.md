## Actions taken

- Verified the recorded commit. At 41d013a the upstream tree holds OFL.txt and both TTFs with the same git blob ids as the files in ofl/asapsharp/, so the shipped files are byte-identical to the upstream files. 41d013a (2026-08-08) predates the merge and is still the HEAD of main. No upstream commits came later.
- Found the gftools-builder config sources/config.yaml at 41d013a. It lists AsapSharp.glyphs and AsapSharp-Italic.glyphs (both in sources/) and defines axisOrder and a per-file STAT.
- Build-tested the config at 41d013a:
  - gftools-builder3 (fontc) built both VFs. functional_gate.py returned PASS for both styles against the shipped fonts: same cmap (652 codepoints), shaping, rendering, names, line spacing and advances.
  - builder3 does not read the config's stat: and axisOrder keys. Its STAT, generated by axisregistry build_stat, gained a SOFT axis value ('Sharp' = 0) inferred from the family name and lists wght before wdth.
  - The Python gftools builder also passed the gate for both styles. Its output matched the shipped binaries in every table except head (modification date and checksum) and the numbering of name IDs 256 and up (the same strings, allocated to different IDs).
- Added config_yaml: "sources/config.yaml" to the source block.
