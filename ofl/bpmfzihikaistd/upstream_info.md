**Model**: Claude Opus 5.5
**Date**: 2026-09-27

## Initial state

- METADATA.pb had `repository_url: "https://github.com/ButTaiwan/bpmfvs"` and `commit: "20f741c18bb917b63576293906c01e82ddfce032"` (2025-12-13, "Update build-ttf.yml"), no `config_yaml`, and the family directory had no override `config.yaml`.
- The earlier upstream_info.md (preserved below) had flagged that commit as wrong: the binary was built in the fork aaronbell/bpmfvs, and the exact build commit was left as an open question.

## Actions taken

- Checked the repo archive mirror of ButTaiwan/bpmfvs against `git ls-remote` (master `fa20c2b`). The fork was merged upstream by PR #23 on 2026-03-27 (merge `97a8ead`, whose tree is identical to the fork head `8fa2d3a`); the fork has no unmerged commits, so `repository_url` was left unchanged.
- Searched the upstream history for the git blob of the shipped `BpmfZihiKaiStd-Regular.ttf` (`51da0cbb7235`, 17497872 bytes). It first appears as `fonts/BpmfZihiKaiStd-Regular.ttf` in `8fa2d3a6f503` (github-actions "Update generated fonts", 2026-02-09 22:50:25 -0800), the CI build of `a179432` ("Update ZihiKaiStd.ttf", a new `srcfonts/ZihiKaiStd.ttf`). google/fonts commit `f55b8f2bb` uploaded it 70 seconds later (22:51:35 -0800). The two files have the same sha256.
- Traced every earlier binary of this family in google/fonts to an upstream CI commit: `605f9ce` to `c01ae3a`, `c32b272` to `720110f`, `ced2e84` to `44ede54`, and `5606321` (google/fonts `72cd1d1f6`, 22:31:49 -0800) to `0333c47`. The `0333c47` build differs from the shipped font in the `OS/2` (typo and win vertical metrics), `glyf` (one outline, uni2469), `loca` and `head` tables, so the Bpmf Huninn and Bpmf Iansui commit is not correct for this family.
- Confirmed that `20f741c` does not match the shipped font: its own `outputs/BpmfZihiKaiStd-Regular.ttf` is Version 1.600 with 1024 units per em, 32981 glyphs and family name "Bpmf Zihi KaiStd Regular". The shipped font is Version 1.610 with 1000 units per em and 32996 glyphs.
- Checked the later upstream commits: none were made between `8fa2d3a` and the google/fonts merge (PR #10173, 2026-02-11). The CI rebuild at `fa20c2b` (2026-03-27) differs from the shipped font only in the `head` table (build timestamp and checksum).
- Searched every commit of the upstream history for a gftools-builder config and for .glyphs/.ufo/.designspace sources and found none. The font is generated by `make_font.rb` (Ruby, otfccdump/otfccbuild, `decompose.py`) from `srcfonts/ZihiKaiStd.ttf`, a compiled TTF (Zihi Kai Std 1.100) committed directly to the repository (by But Ko since 2020, and in five revisions by Aaron Bell in 2026). It is not listed in `upstream_sources.json`, and no source for it exists in the repository.
- Probed gftools-builder with that TTF as a source. builder3 (e851b8b) reported "Unrecognized source" and the Python builder raised a ValueError. No override config.yaml was written.
- Set `commit` to `8fa2d3a6f50348d870ea273cb35a7879a82dbac8`.

## Final state

- `source { repository_url: "https://github.com/ButTaiwan/bpmfvs" commit: "8fa2d3a6f50348d870ea273cb35a7879a82dbac8" }`. This commit contains the shipped binary byte for byte and the sources that produced it.
- No `config_yaml` and no override config.yaml. gftools-builder has no operation that compiles a TTF input or adds the Bopomofo annotations, and the only font input upstream is a compiled TTF with no source. Status: missing_config.
- To reproduce the font, run `ruby make_font.rb` at the recorded commit and skip `update_sources.rb`, because that script replaces `srcfonts/` with the newest upstream base fonts.
- Corrections to the text below: the build commit is now known; the fork's commits are part of ButTaiwan/bpmfvs. The `source` block with `repository_url` was added by `44d5c78d8` on the PR #10173 branch.
