## Actions taken

- The recorded commit was verified. The shipped MPLUS1Code[wght].ttf is byte-identical to fonts/MPLUS1Code/variable/MPLUS1Code[wght].ttf at 4bf6982 (and at 06feee4, the Aaron Bell commit it merges). All inputs of its build (MPLUS1-code.glyphs, MPLUS1Code.designspace, kana_glyphs.txt, MPLUS-1.glyphs, MPLUS-Kanji.glyphs, sources/scripts, the Makefile) are identical at 06feee4 and 4bf6982, and the 18 upstream commits between 4bf6982 and the google/fonts merge touched only sources/MPLUS3/MPLUS-3.glyphs. The commit was kept.
- The upstream build was examined. sources/MPLUS1Code/config.yaml builds sources/MPLUS1Code/MPLUS1Code.designspace, whose three sources (merged_ufo/MPLUS1Code-Thin/Regular/Bold.ufo) are generated by the Makefile: sources/scripts/merge.py takes the width-50 masters of MPLUS1-code.glyphs, adds the 246 kana glyphs listed by name in kana_glyphs.txt from M PLUS 1 instances that sources/scripts/instancer.py interpolates with the designspace rules removed, clears the kerning, adds every Kanji glyph from interpolated Kanji instances and replaces the features with sources/scripts/code.fea. Building that config from a clean checkout failed in gftools builder (merged_ufo/MPLUS1Code-Thin.ufo missing) and in gftools-builder3 (the UFO sources cannot be loaded).
- A config-only reconstruction was tested: MPLUS1-code.glyphs with includeSubsets (the 191 kana code points from MPLUS-1.glyphs, all Kanji glyphs) and a wdth=100 subspace. gftools-add-ds-subsets stopped with StopIteration because it passes the donor instance name "M+ 1p Regular" to fontmake as an unescaped regular expression. With the name escaped in a diagnostic wrapper, fontmake rejected the merged masters as incompatible: gftools interpolates the donor instances with the bracket rules applied, so kana such as za-hira, go-kata and gu-kata change structure at Bold. The kerning reset and the code.fea features cannot be expressed in a gftools-builder config either. Selecting the kana by name can be expressed on gftools main (includeSubsets glyphNamesFile, available since gftools v0.9.994), but not in the gftools checkout used for the test nor in gftools-builder3.
- Built alone, MPLUS1-code.glyphs gives the M PLUS Code Latin glyph set (740 glyphs, 716 code points, wdth and wght axes) under the name M PLUS 1 Code, not this family (6747 glyphs, 6463 code points, wght only). No override config.yaml was added and config_yaml was not set.

## Final state

- METADATA.pb is unchanged; commit 4bf69824e45a175b9121b248c46abff103569051 is correct.
- The family has no gftools-builder config that builds it from the committed sources. It builds only through the upstream Makefile (make prep instancer merge compile), whose intermediate UFOs are not committed.
